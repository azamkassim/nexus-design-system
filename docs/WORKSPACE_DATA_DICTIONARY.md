# Financing Workspace Structure and Data Ownership

## Assessment sections

| Section | Primary content | Default source | RM manual entry |
| --- | --- | --- | --- |
| Proposal Snapshot | request, amount, product, purpose | application / request | confirm exceptions |
| Customer & Group | identity, business, group | governed customer evidence | relationship context |
| Ownership & Management | directors, shareholders, management | documents / external checks | qualitative assessment |
| Facility & Purpose | amount, tenure, pricing, purpose | proposal / approved terms | structuring judgement |
| Contract / Revenue Base | contract terms, employer, milestones | contract / SST / evidence | interpretation where needed |
| Financials & Cash Flow | historical, ratios, projections | statements / CFFS | assumptions requiring confirmation |
| Account Conduct & External Checks | account behaviour / bureau | statements / checks | interpretation |
| Security | asset, valuation, ranking, coverage | legal/valuation evidence | exception commentary |
| Risk, Mitigants & Recommendation | strengths, weaknesses, mitigants | derived from evidence | RM credit judgement |
| Policy, Conditions & Approval | policy tests, CP/DC, exceptions | governed policy | rationale for exception |
| Decision & Team 2 Handoff | approval, conditions, outstanding actions | human decision | handoff confirmation |

## Field-level metadata

Every material field should support:

- canonical field ID;
- value;
- effective date / period;
- source;
- source location;
- evidence status;
- entered/extracted/calculated/governed classification;
- owner;
- verification state;
- confidence where inferred;
- reused outputs;
- superseded value history.

## RM entry principle

RM manual entry is reserved for information that is:

- genuinely judgemental;
- not reliably extractable;
- a confirmation of an extracted value;
- an assumption requiring human accountability;
- an approved exception / rationale.

Do not make RMs type values that already exist in verified evidence.

## Reuse destinations

Verified fields can feed:

- Pre-Assessment Memo;
- CAR;
- Executive Summary;
- Credit Committee slides;
- ALK Risk memo/slides;
- ALK memo/slides;
- Team 2 handoff;
- monitoring baseline.

Output-specific prose may differ, but the underlying verified fact remains one canonical value.
