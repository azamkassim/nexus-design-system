# NEXUS Definition of Done

A NEXUS feature is not complete because a screen exists.

## Feature gate

A feature is COMPLETE only when:

- user journey is defined;
- canonical object(s) are identified;
- duplicate data paths are avoided;
- permissions / human gate are defined;
- source/evidence behaviour is clear;
- empty/loading/error/blocked states are handled where applicable;
- responsive behaviour is acceptable;
- build passes;
- key behaviour is tested;
- no confidential demo data exists in public source;
- rollback path is known.

## Workspace gate

A customer workspace is ready to move stage only when:

- required sections reach the stage threshold;
- material facts are verified;
- calculations have lineage;
- assumptions are explicit;
- information gaps are visible;
- policy evaluation is available where applicable;
- material recommendation has human ownership;
- outstanding conditions are carried forward rather than hidden.

## Team 1 → Team 2 handoff gate

Handoff must contain:

- approved facility terms;
- approval reference;
- conditions precedent/subsequent;
- security requirements;
- pricing / profit-rate position;
- disbursement structure;
- unresolved documentation;
- responsible owner;
- due dates;
- evidence links;
- exceptions and approvals.

No silent loss of information is permitted at team boundaries.
